# TILDA_HANDOFF — AINA Évidence

Единый пакет для переноса технической части в сайт на Tilda (собирается в ChatGPT Work). Репозиторий: `Dochsul/-`, ветка `claude/code-setup-plugin-c368la`.

**Версия 2 (обновлено).** Что изменилось: (1) утверждены и внесены цены всех гайдов; (2) готовы автоматическое развёртывание сервера, резервные копии и восстановление; (3) готова доставка PDF по email через SMTP; (4) готова тестовая интеграция Stripe (скрипты и чеклист); (5) безопасность API проверена тестами; (6) фактический запуск CI на GitHub подтверждён. Оплата в рублях по-прежнему **выключена**. Сервер не развёрнут, Stripe не подключён, Tilda мне недоступна.

**Что здесь:** тексты 19 страниц на RU/FR/EN, SEO, T123-компоненты, каталог из 4 позиций, архитектура защищённой выдачи PDF, учёт заказов, платежей, комиссий и возвратов, инструкции по интеграции и результаты тестов.

## 0. Правила, которые нельзя нарушать

1. **Не публиковать черновики.** Консультации, меню и сопровождение — черновики до подтверждения законного права оказывать эти услуги во Франции. Юридические страницы — черновики до заполнения анкеты и проверки юристом.
2. **Не менять утверждённый прайс в Tilda.** Цены консультаций в этот пакет намеренно не перенесены.
3. **Не размещать платные PDF в Tilda** (ни в файлах страниц, ни в Members Area, ни по ссылкам). PDF выдаются только сервером по персональным ссылкам после подтверждённой оплаты (раздел 7).
4. **Не включать реальные платежи** и не создавать фиктивные платежи. Тестовый режим Stripe — только с ключами владельца и только на сервере.
5. **Не вставлять секретные ключи** в Tilda, в блоки T123 или в переписку. В блоках есть только публичный адрес API (`data-api`).
6. **Не выдумывать** реквизиты, отзывы, дипломы, цены и содержание гайдов. Недостающее собрано в `docs/ANKETA.md`.

«Не опубликован» означает: нет PDF-файлов на сервере и содержание не подтверждено автором (`published`/`contentConfirmed` в `src/config/catalog.mjs`). После загрузки файлов (`node scripts/verify-files.mjs`) и вашего подтверждения владелец или разработчик меняет флаги и пересобирает пакет.

**Рубли.** В русской версии показываются обе цены. Оплата принимается **только в евро**: оплата в рублях выключена до подтверждения законного рабочего платёжного канала. В блоке на русском для этого есть поясняющее сообщение.

**Установка блока магазина (страницы 8 и 9, каждый язык):**
1. Добавьте блок **T123 (HTML-код)**, вставьте целиком `tilda/components/01-shop.<язык>.html`.
2. В первой строке блока `data-api=""`: впишите адрес API после развёртывания (например `https://api.<домен>`), без «/» в конце. Пока API нет, оставьте пустым: блок покажет гайды с ценами и «Оплата пока не подключена».
3. Проверьте ссылки на юридические страницы внутри блока (`/ru/legal/terms-of-sale/` и т. п.) и при необходимости замените на фактические адреса.
4. На сервере в `ALLOWED_ORIGINS` укажите точный адрес сайта Tilda, иначе браузер не пустит запросы к API (CORS).

**Как работает блок:**
- Товары, цены и доступность берёт с сервера (`GET /api/catalog`). Встроенные цены только отображаются.
- Купить можно только опубликованный товар с подтверждённой ценой и только когда на сервере включены платежи. Каждый цифровой товар покупается в одном экземпляре.
- Комплект и входящий в него гайд нельзя купить вместе: блок оставляет комплект, сервер отклоняет такой заказ (`bundle_overlap`).
- Перед оплатой обязательны два согласия: условия продажи и политика возврата; немедленная поставка цифрового контента с отказом от права на отзыв (ст. L221-28 Code de la consommation). Без них сервер не создаёт оплату.
- Переход только на `https://`-адрес, который вернул сервер (Stripe Checkout).

## 7. Выдача PDF после подтверждённой оплаты

**Почему не средствами Tilda.** Файлы, загруженные в Tilda, отдаются с публичного CDN по постоянным ссылкам. Members Area закрывает **страницы**, но, насколько мне известно, не делает закрытыми **ссылки на файлы**: пересланная ссылка будет открываться у всех. **Проверить в Tilda.** Пока это не опровергнуто, Tilda для выдачи платных PDF не используется.

**Реализованная схема:**

```
Tilda (блок T123) ──POST /api/checkout──► API: заказ pending_payment, цена с сервера
        │                                   └─► Stripe Checkout (страница оплаты Stripe)
        ◄── редирект на Stripe ─────────────┘
Покупатель платит на Stripe ──► Stripe ──подписанный webhook──► API /api/webhooks/stripe
                                                       ├─ проверка подписи HMAC, срока, повторов
                                                       ├─ сверка суммы и валюты с заказом
                                                       ├─ проверка страны (санкционный список → ручная проверка)
                                                       ├─ заказ → paid, запись платежа и комиссии
                                                       └─ 1 персональный токен на каждый PDF → письмо покупателю
Покупатель ──GET /api/download/<токен>──► PDF из закрытой папки (не публичной)
```

- Токен 256 бит. В базе хранится только его хеш. Срок 7 дней, до 5 скачиваний (предложение; вопрос H42 анкеты). Ответ без кеширования.
- Повторное или поддельное событие ничего не выдаёт. Возврат полной суммы отзывает ссылки.
- Страница «Спасибо» (компонент 05) ничего не подтверждает: доступ даёт только сервер.

**Вариант через корзину Tilda + webhook Tilda** не реализован. Формат данных Tilda я не мог проверить, а подтверждение оплаты от Tilda не подписано так же надёжно, как событие Stripe.

---

**Доставка по email.** После подтверждения оплаты сервер ставит в очередь одно письмо на языке покупателя (RU, FR или EN) с персональными ссылками на каждый PDF (для комплекта — три), сроком и лимитом скачиваний, номером заказа и адресом поддержки. **PDF не прикладываются** к письму: вложение нельзя отозвать после возврата. Письмо уходит через любой SMTP-сервис (`SMTP_*`, `CLIENT_CHANNEL=smtp`); статус «отправлено» ставится только после ответа почтового сервера. При сбое письмо остаётся в очереди и отправка повторяется (до 8 попыток). Если письмо не пришло, владелец может выпустить новую ссылку.

## 8. Платежи

**Stripe (тестовый режим), шаги владельца:**
1. Создать аккаунт Stripe (бизнес во Франции). **Нужно разрешение владельца.** Регистрация бесплатна, комиссии — по тарифу Stripe.
2. В тестовом режиме взять `sk_test_…` и создать webhook `https://<api>/api/webhooks/stripe` с событиями:
   - `checkout.session.completed`
   - `checkout.session.async_payment_succeeded`
   - `checkout.session.async_payment_failed`
   - `checkout.session.expired`
   - `charge.refunded`
3. Ключи (`STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`) — **только** в переменных окружения сервера.
4. Тестовая покупка картой `4242 4242 4242 4242`. Затем отказ (`4000 0000 0000 0002`), возврат из Dashboard и проверка, что ссылки отозваны.
5. Боевой режим — только после разрешения владельца (`docs/PAYMENTS.md`, раздел 5).

**PayPal Business, перевод, Revolut:** не подключены. Варианты и условия — `docs/PAYMENTS.md`.

**Рубли и клиенты из России:**
- Цена 2 000 ₽ хранится и показывается.

Минимальные постоянные расходы после запуска: VPS (порядка 5–7 € в месяц, цену проверить при заказе, `docs/HOSTING.md`); почта, внешние копии и сертификат укладываются в бесплатные лимиты; Stripe берёт комиссию только с каждого платежа.

## 13. Развёртывание API (решение владельца, платно)

**Рекомендация и сравнение вариантов** (Cloudflare, Supabase, Vercel, Render, Fly.io, VPS, ограничения коммерческого использования, расходы): `docs/HOSTING.md`. Коротко: бесплатных тарифов, которые одновременно дают постоянную базу, закрытое хранилище файлов, постоянный приём подтверждений оплаты и разрешённое коммерческое использование, я не нашёл. Нужен **один маленький VPS в ЕС** (порядка 5–7 € в месяц, точную цену показывает консоль заказа). Всё остальное укладывается в бесплатные лимиты. **Ничего не куплено, нужно ваше разрешение.**

Пошаговая инструкция: `docs/DEPLOY.md` (cloud-init, `deploy.sh` с проверкой конфигурации и автоматическим откатом, Caddy с автоматическим HTTPS, контейнер ежедневных зашифрованных копий). Автоматическая выкладка из GitHub есть, но она **только ручная** и не работает, пока владелец сам не включит её (`DEPLOY_ENABLED`, окружение `production` с подтверждением, секреты). Переменные окружения — `.env.example`:

| Переменная | Значение для связки с Tilda |
|---|---|
| `SITE_URL`, `API_DOMAIN` | адрес API (например `https://api.<домен>`): он попадёт в ссылки из писем |
| `ALLOWED_ORIGINS` | точный адрес сайта Tilda (например `https://<домен>`) |
| `CHECKOUT_SUCCESS_URL` | страница «Спасибо» в Tilda, `{locale}` подставляется: `https://<домен>/{locale}/merci/` |
| `CHECKOUT_CANCEL_URL` | страница магазина: `https://<домен>/{locale}/shop/` |
| `PAYMENTS_ENABLED` | `false` до разрешения владельца; боевой ключ Stripe требует ещё `LIVE_PAYMENTS_APPROVED=owner-approved` |
| `ENABLED_CURRENCIES` | `EUR`; `RUB` только вместе с `RUB_PAYMENTS_APPROVED=owner-approved` |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | только в `.env` на сервере |
| `OWNER_CHANNEL`, `CLIENT_CHANNEL`, `SMTP_*`, `MAIL_FROM` | почта владельцу и покупателям; `file` в production запрещён |
| `BACKUP_PASSPHRASE`, `S3_*`, `BACKUP_PING_URL` | шифрованные копии, внешнее хранилище, сторожевой пинг |

PDF кладутся на сервер в `private/products/<sku>.pdf` и проверяются `node scripts/verify-files.mjs`. Не в git, не в Tilda. **Оригинальные PDF находятся в вашей библиотеке ChatGPT; на сервер их копируете вы, а не пакет из репозитория.**

Серверу в production **запрещено** стартовать со слабой солью, без https, с «файловым» каналом уведомлений, с битыми ключами Stripe и без явных переключателей владельца для боевого режима и рублей (`server/config.mjs`, 10 проверок).
