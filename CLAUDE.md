# CLAUDE.md — AINA Évidence

Инструкции для Claude Code в этом репозитории. Держите файл коротким и актуальным. Подробности — в `docs/`.

## Что это

Коммерческий сайт и небольшой API для **AINA Évidence** (владелец: Айна Мусхаджиева, консультант-диетолог и нутрициолог, работает онлайн из Франции). Сайт на трёх языках: `ru`, `fr`, `en`. Магазин цифровых гайдов, заявки на консультации, юридические страницы.

**Текущий статус:** платежи выключены, публикация не выполнена, юридические документы — черновики, цены не подтверждены. См. `PROGRESS.md`.

## Карта репозитория

| Путь | Что |
|---|---|
| `src/config/business.mjs` | Данные бизнеса. Неизвестное = `null`. Единственное место для реквизитов |
| `src/config/catalog.mjs` | Цифровые продукты. Цены `null` до подтверждения |
| `src/config/services.mjs` | Услуги консультаций (цены из прежнего сайта, не подтверждены) |
| `src/content/{ru,fr,en}.mjs` | Тексты сайта. Ключи должны совпадать во всех трёх языках |
| `src/legal/{fr,en,ru}.mjs` | Юридические документы. Французский — обязательный |
| `src/render.mjs` | HTML-компоненты и layout |
| `src/build.mjs` | Сборка `dist/`, шлюз публикации (`--prod`) |
| `site/static/` | CSS, `app.js`, self-hosted шрифты, favicon |
| `server/` | API на Node.js без зависимостей: заявки, заказы, webhook Stripe, загрузки, очередь писем |
| `tests/` | `node --test`: сервер (31) и сайт (15) |
| `scripts/check.mjs` | Проверки собранного `dist/` и поиск секретов |
| `scripts/smoke.cjs` | Браузерная проверка против запущенного сервера (Playwright) |
| `docs/` | `ARCHITECTURE.md`, `PAYMENTS.md`, `SECURITY.md`, `BRAND.md`, `ANKETA.md` |
| `private/products/` | PDF-гайды. **Не в git**, выдаются только через API |
| `data/` | SQLite и очередь писем. **Не в git** |

## Команды

```bash
npm test                 # все тесты (без зависимостей)
npm run build            # dev-сборка в dist/ (заглушки подсвечиваются в документах)
npm run build:prod       # продакшен-сборка: падает, пока не заполнена анкета
npm run check            # проверки dist/ и секретов
npm run serve            # API + dist/ на PORT (по умолчанию 8080)
SMOKE_URL=http://localhost:8080 npm run smoke   # браузерная проверка (нужен Playwright)
```

Перед каждым коммитом: `npm test && npm run build && npm run check`.

## Жёсткие правила

1. **Не выдумывать.** Не добавлять отзывы, кейсы, результаты, дипломы, номера сертификатов, цены, содержание продуктов, SIREN, адреса, сроки хранения, условия возврата и юридические формулировки сверх шаблона. Недостающее — токен `{{...}}` или `null` в конфиге.
2. **Публикация только по команде владельца.** Не запускать деплой, не включать `PAYMENTS_ENABLED`, не публиковать `dist/` на хостинге. CI не деплоит.
3. **Платежи** выключены по умолчанию. Реальные ключи Stripe — только после разрешения владельца и по чеклисту из `docs/PAYMENTS.md`.
4. **Сторонние сервисы, плагины, платные подписки** — только с разрешения владельца. Пример: VPS, домен, Stripe-аккаунт, почтовый провайдер, Telegram-бот для уведомлений (бесплатен, но данные заявок пойдут третьей стороне; нужно решение и обновление политики).
5. **Санкции.** Не обходить ограничения (чужие аккаунты, посредники, смена страны). Список `business.blockedCountries` — заглушка, окончательное решение за юристом.
6. **Персональные данные.** Форма не принимает медицинские анализы и диагнозы (сервер отклоняет такие заявки). Не логировать тела запросов. IP хранятся только соленым хешем.
7. **CSP.** Нельзя добавлять inline-скрипты, обработчики `on*=` и атрибуты `style=`. Внешние ресурсы не подключать без решения (сейчас шрифты и всё self-hosted).
8. **Контраст.** Текст на золоте — только тёмный (`--ink`). Золото не используется как цвет текста на светлом фоне.
9. **Language parity.** Ключи в `src/content/*.mjs` и `src/legal/*.mjs` должны совпадать. Тесты это проверяют.
10. **Коммиты:** только в ветку `claude/code-setup-plugin-c368la`, без PR, если владелец не попросит.

## Что делать в конце сессии

1. Обновить `PROGRESS.md`: сделано, проверено чем, открыто, решения.
2. Запустить `npm test && npm run build && npm run check`.
3. Закоммитить и отправить в ветку.

## Экономия контекста и лимитов

- Большие файлы (`src/content/*.mjs`, `site/static/styles.css`, `src/render.mjs`) читать по диапазонам через `grep -n`.
- Не перечитывать файлы, изменённые только что, если изменение прошло без ошибки.
- Сабагенты не нужны для задач из 1–2 шагов.
- Между задачами `/clear`, в длинных сессиях `/compact`.
- Регулярные задачи по расписанию не создавать без просьбы владельца.
