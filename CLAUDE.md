# CLAUDE.md — Global Aina Nutrition

Инструкции для Claude Code в этом репозитории. Читай перед работой, держи короткими и актуальными.

## Что это за проект

Статический одностраничный сайт для онлайн-консультаций по питанию. Владелец: Айна Мусхаджиева (France). Весь контент на русском.

- Бренд и правила стиля: `docs/BRAND.md` (читать при любых правках текстов и оформления).
- Текущее состояние и открытые вопросы: `PROGRESS.md` (читать в начале сессии, обновлять в конце).
- Название «AINA Évidence» из запроса владельца в репозитории не найдено. Не вносить его в сайт без подтверждения (см. `docs/BRAND.md`, раздел 1).

## Структура

| Файл | Назначение |
|---|---|
| `index.html` | Весь сайт: CSS и JS встроены, около 1500 строк |
| `privacy.html`, `terms.html`, `refund.html` | **Черновики** юридических страниц, `noindex`, до проверки юристом |

| `robots.txt`, `sitemap.xml` | SEO. Домен `globalainanutrition.com` ещё не подтверждён |

| `scripts/smoke.cjs` | Браузерная проверка через Playwright (нужен установленный браузер) |

| `.claude/settings.json` | Общие настройки Claude Code для проекта |
| `README.md`, `QUICKSTART.md` | Документация для владельца |

## Команды проверки

```bash
node scripts/check.mjs            # статические проверки, обязательно перед коммитом
node scripts/smoke.cjs            # браузерная проверка (нужен Playwright + Chromium)
python3 -m http.server 8000       # локальный просмотр
```

Перед коммитом запускай `scripts/check.mjs`. Если он падает, исправь причину, а не отключай проверку.

## Правила работы с кодом

1. **Один файл — одна ответственность.** Не разбивай `index.html` на модули без необходимости: это статический сайт без сборщика, и так проще хостить.
2. **Не добавляй сторонние сервисы и зависимости без разрешения владельца.** Это касается платных сервисов, аналитики, трекеров, форм-бэкендов, npm-пакетов для сайта, A/B-тестов, чатов, рекламных пикселей.
3. **Персональные данные.** Заявки содержат данные о здоровье (цель обращения). Не логировать их (`console.log`), не отправлять в сторонние сервисы без согласия владельца и обновления политики конфиденциальности.
4. **Форма.** `FORM_ENDPOINT` в `index.html` пуст намеренно. Если владелец выберет сервис для приёма заявок: добавь его origin в CSP `connect-src`, обнови раздел 5 `privacy.html`, запусти `scripts/check.mjs`.
5. **CSP.** Политика задана `<meta http-equiv>` в каждом HTML. Новые внешние ресурсы (скрипты, шрифты, стили) нужно добавить в CSP, иначе они будут заблокированы.
6. **Не утверждай, что что-то работает, пока не проверил.** Для сайта это значит: прогнать `check.mjs` и, если есть браузер, `smoke.cjs`. Если проверка невозможна (например, CDN недоступен из контейнера), так и напиши.
7. **Языки.** Весь пользовательский текст — на русском. Комментарии в коде — на русском или английском, но единообразно в рамках блока.
8. **Нельзя публиковать юридические тексты, отзывы, кейсы, цифры результатов и медицинские утверждения** без подтверждения владельцем.
9. **Коммиты:** на ветку `claude/code-setup-plugin-c368la`, без PR, если владелец не попросит. Сообщения коммитов — кратко, по-русски или по-английски.

## Экономия контекста и лимитов

- `index.html` большой (около 55 КБ). Не читай его целиком. Ищи по `grep -n` (id, класс, `<section`) и читай нужный диапазон строк.
- Для больших правок в одном файле используй `Edit` с точными фрагментами, а не переписывание файла.
- Не запускай сабагенты для задач, которые решаются в одном-двух вызовах.
- Между разными задачами используй `/clear`, а при длинной сессии — `/compact`.
- Не создавай повторяющиеся задачи по расписанию без просьбы владельца: они расходуют лимиты подписки.

## Конец сессии

1. Обнови `PROGRESS.md`: что сделано, что проверено и чем, что осталось, какие решения приняты.
2. Запусти `node scripts/check.mjs`.
3. Закоммить и отправь в ветку (см. правило 9).
