# CLAUDE.md — AINA Évidence

Инструкции для Claude Code в этом репозитории. Держите файл коротким и актуальным. Подробности — в `docs/`.

## Что это

Техническая часть для **AINA Évidence** (владелец: Айна Мусхаджиева, работает онлайн из Франции). **Основной сайт собирается в Tilda через ChatGPT Work**; этот репозиторий даёт пакет для Tilda (`TILDA_HANDOFF.md`, `tilda/`), API для оплаты и защищённой выдачи PDF, учёт и резервный статический сайт на `ru`/`fr`/`en`.

**Текущий статус:** платежи выключены, API не развёрнут, Stripe не подключён, юридические документы — черновики. Консультации, меню и сопровождение — черновики до подтверждения права оказывать их во Франции. **Цены утверждены:** АБКМ 1 000 ₽ / 9,90 €; сон 0–18 лет 1 000 ₽ / 9,90 €; прикорм 800 ₽ / 7,90 €; комплект 2 000 ₽ / 19,90 €. Оплата в рублях выключена до законного рабочего канала. См. `PROGRESS.md`.

## Команды

```bash
npm test                 # все тесты (без зависимостей)
npm run build            # dev-сборка в dist/ (заглушки подсвечиваются в документах)
npm run build:prod       # продакшен-сборка: падает, пока не заполнена анкета
npm run check            # проверки dist/ и секретов
npm run serve            # API + dist/ на PORT (по умолчанию 8080)
SMOKE_URL=http://localhost:8080 npm run smoke   # браузерная проверка (нужен Playwright)
npm run tilda            # пересобрать пакет для Tilda (тексты, SEO, компоненты)
npm run e2e:tilda        # браузерный e2e блока магазина (нужен Playwright)
npm run accounting:export -- --from 2026-01-01 --to 2026-12-31   # CSV для бухгалтера
node scripts/backup.mjs / restore.mjs <latest|s3-latest> [--verify-only|--force]   # копии (нужен BACKUP_PASSPHRASE)
node scripts/stripe-test.mjs check|session|endpoint   # только тестовые ключи; боевой ключ отклоняется
node scripts/verify-files.mjs   # PDF на месте, это PDF, SHA-256
```

Перед каждым коммитом: `npm test && npm run build && npm run check && npm run tilda` (и закоммитить изменения в `tilda/`).

## Жёсткие правила

1. **Не выдумывать.** Не добавлять отзывы, кейсы, результаты, дипломы, номера сертификатов, цены, содержание продуктов, SIREN, адреса, сроки хранения, условия возврата и юридические формулировки сверх шаблона. Недостающее — токен `{{...}}` или `null` в конфиге.
2. **Публикация только по команде владельца.** Не запускать деплой, не включать `PAYMENTS_ENABLED`, не публиковать `dist/` на хостинге. CI не деплоит; `deploy.yml` только ручной и выключен, пока владелец сам не поставит `DEPLOY_ENABLED`, окружение и секреты.
3. **Платежи** выключены по умолчанию. Реальные ключи Stripe — только после разрешения владельца и по чеклисту из `docs/PAYMENTS.md`. Боевой ключ вдобавок требует `LIVE_PAYMENTS_APPROVED=owner-approved`, рубли — `RUB_PAYMENTS_APPROVED=owner-approved`; эти защиты нельзя ослаблять и обходить.
4. **Сторонние сервисы, плагины, платные подписки** — только с разрешения владельца. Пример: VPS, домен, Stripe-аккаунт, почтовый провайдер, Telegram-бот для уведомлений (бесплатен, но данные заявок пойдут третьей стороне; нужно решение и обновление политики).
5. **Санкции.** Не обходить ограничения (чужие аккаунты, посредники, смена страны). Список `business.blockedCountries` — заглушка, окончательное решение за юристом.
6. **Персональные данные.** Форма не принимает медицинские анализы и диагнозы (сервер отклоняет такие заявки). Не логировать тела запросов. IP хранятся только соленым хешем.
7. **CSP.** Нельзя добавлять inline-скрипты, обработчики `on*=` и атрибуты `style=`. Внешние ресурсы не подключать без решения (сейчас шрифты и всё self-hosted).
8. **Контраст и палитра.** Утверждённая палитра: `#FFF4E9 #F3D6CF #E4D3E4 #B4883E #74283F #174532`. Текст на золоте — только тёмный (`#2E2427`). Золото не используется как цвет текста на светлом фоне (2.97:1).
9. **Language parity.** Ключи в `src/content/*.mjs` и `src/legal/*.mjs` должны совпадать. Тесты это проверяют.
10. **Коммиты:** только в ветку `claude/code-setup-plugin-c368la`, без PR, если владелец не попросит.
11. **Tilda.** Платные PDF никогда не размещаются в Tilda (публичный CDN). Выдача только через API по токенам после подписанного webhook. В T123-блоках нет секретов; CSS только под `.ae`.
12. **Цены.** Утверждённый прайс консультаций в Tilda не менять и в пакет не переносить. Цены гайдов (см. выше) вносить только как утвердил владелец. Оплата в RUB выключена (`ENABLED_CURRENCIES=EUR`) до законного рабочего канала.
13. **Не заявлять непроверенное.** Что не запускалось (Docker на сервере, реальный Stripe/SMTP/S3, Tilda), так и называть. Секреты — только в `.env` на сервере, никогда в чат, репозиторий или Tilda.

## Что делать в конце сессии

1. Обновить `PROGRESS.md`: сделано, проверено чем, открыто, решения.
2. Запустить `npm test && npm run build && npm run check`.
3. Закоммитить и отправить в ветку.

## Экономия контекста и лимитов

- Большие файлы (`src/content/*.mjs`, `site/static/styles.css`, `src/render.mjs`) читать по диапазонам через `grep -n`.
- Не перечитывать файлы, изменённые только что, если изменение прошло без ошибки.
- Сабагенты не нужны для задач из 1–2 шагов.
- Между задачами `/clear`, в длинных сессиях `/compact`.
- Регулярные задачи по расписанию не создавать без просьбы владельца.
