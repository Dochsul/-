# Окончательная инструкция: развёртывание с iPhone и компьютера

Цель: работающий API (оплаты, выдача PDF, письма, админ-панель, копии) на одном сервере. Большая часть команд уже написана: вы отвечаете на вопросы и подтверждаете решения.

**Главное правило:** никаких покупок и подписок, пока вы не скажете «да» на конкретный шаг. Боевые платежи включаются только после одобрения Merchant и вашего письменного решения.

Условные обозначения:
- 📱 — делается на iPhone (Safari и приложение SSH).
- 💻 — делается на компьютере (Terminal на Mac или PowerShell на Windows).
- 🤖 — делает ассистент в репозитории или подсказывает текст.
- 💸 — требует покупки или подписки: **не делать до вашего «да»**.
- ⏸ — стоп-точка.

---

## Фаза A. Бесплатно, можно сделать сейчас (до одобрения Revolut)

**A1. Пароли и менеджер.** 📱 Установите менеджер паролей (iCloud Keychain встроен в iPhone). Заведите записи: «AINA — Hetzner», «AINA — Brevo», «AINA — Backblaze», «AINA — Revolut», «AINA — домен», «AINA — админ-панель», «AINA — копии (BACKUP_PASSPHRASE)». Пароли не записываются в заметки и не отправляются в чат.

**A2. Регистрационные данные (закрытый файл).** 💻 На компьютере:
1. Откройте папку проекта, скопируйте `docs/registration.template.json` в `private/registration.json`.
2. Заполните поля из ваших документов. Что не знаете — оставьте `null`.
3. Зашифруйте копию:
   ```
   read -rs PASS && printf '%s' "$PASS" | node scripts/registration-seal.mjs seal; unset PASS
   ```
   Пароль (не короче 20 символов) сохраните в менеджере паролей.
4. Файл `private/registration.json.enc` положите в iCloud Drive (📱 Файлы). Файл `private/registration.json` не копируйте в облако открытым.
5. Проверьте: `git status` не показывает `private/`.

**A3. Домен: есть ли уже свой?** 📱 Ответьте в чат на вопрос: есть ли у вас домен (например, тот, на котором работает Tilda или сайт бизнеса)?
- **Если да:** домен не покупается. Адрес API будет поддоменом, например `api.<ваш-домен>`. Ничего нового покупать не нужно.
- **Если нет:** домен — отдельная покупка (💸), решите до этапа C.
- Проверить привязку Tilda: в Tilda откройте настройки проекта → раздел «Домен»; записанный там адрес и есть ваш домен.

**A4. Почта Brevo (бесплатно).** 📱 Откройте https://www.brevo.com, зарегистрируйтесь (бесплатный тариф, 300 писем в день). Если форма просит карту, остановитесь и сообщите ассистенту. Сохраните логин и SMTP-ключ в менеджер паролей. Подтверждение домена отправителя — после этапа C (нужен домен).

**A5. Хранилище копий Backblaze B2 (бесплатно до 10 ГБ).** 📱 Откройте https://www.backblaze.com/cloud-storage, зарегистрируйтесь, проверьте, что тариф бесплатный. Создайте закрытый бакет (Private) в ЕС и ключ приложения, ограниченный этим бакетом. `keyID` и `applicationKey` сразу сохраните в менеджер паролей. Если просит карту — ⏸ сообщите ассистенту.

**A6. Ключ для входа на сервер (бесплатно).** 📱 Установите SSH-приложение: Termius или Blink Shell (проверьте условия бесплатного тарифа в App Store). Создайте ключ Ed25519 внутри приложения и скопируйте **публичный** ключ (строка, начинается с `ssh-ed25519`). Приватный ключ не копируйте и не отправляйте.

**A7. Адреса сайта и оплаты (решите заранее).** 📱 Откройте Tilda и проверьте, есть ли страница «спасибо» после заказа (например `/ru/merci`). Ответьте ассистенту, какие адреса будут: страница успеха и страница отмены для каждого языка. Они нужны для `CHECKOUT_SUCCESS_URL` и `CHECKOUT_CANCEL_URL`.

**A8. Revolut Business (ожидание).** Заявка подана. Пока её одобряют, ничего дополнительно делать не нужно. Письменный вопрос Revolut по цифровым товарам — 📱 в поддержку приложения (сохраните ответ в почте).

## Фаза B. После одобрения Revolut Business (всё ещё бесплатно)

**B1. Ключ песочницы.** 📱/💻 В Revolut Business найдите раздел Merchant / API и создайте ключ песочницы (точный путь уточняйте в интерфейсе: он меняется). Сохраните в менеджер паролей. Ключ в чат не отправляйте.

**B2. Webhook.** В настройках Merchant создайте webhook:
- адрес: `https://api.<ваш-домен>/api/webhooks/revolut` (адрес станет рабочим после фазы C; можно создать сейчас с уже известным адресом домена);
- события: `ORDER_COMPLETED`, `ORDER_CANCELLED`, `ORDER_PAYMENT_DECLINED`, `ORDER_PAYMENT_FAILED`;
- сохраните секрет `wsk_…` в менеджер паролей.

**B3. Письменный ответ по цифровым товарам.** Сохраните в почте. Без него боевой режим не включается.

## Фаза C. Сервер и домен (💸 только после вашего «да»)

**C1. Решение о расходах.** ⏸ Напишите ассистенту «да, Hetzner» (и «да, домен», если домена нет). Без этого шага ассистент ничего не создаёт.

**C2. Hetzner Cloud.** 📱 Safari → https://console.hetzner.cloud → регистрация (email, пароль, телефон, подтверждение личности, способ оплаты — вводите сами).
1. **Security → SSH Keys → Add SSH key:** вставьте публичный ключ из A6. Название: `iphone`.
2. **Servers → Add Server:**
   - Location: Falkenstein, Nuremberg или Helsinki (ЕС).
   - Image: **Ubuntu 24.04**.
   - Type: **самый маленький Shared vCPU с 2 vCPU и не меньше 2 ГБ RAM** (CX22 или его преемник — выберите актуальный в списке; цену смотрите там же).
   - Networking: **Public IPv4** включён (нужен, чтобы домен указывал на сервер).
   - SSH key: `iphone`.
   - **Cloud config (User data):** вставьте текст `deploy/cloud-init.yaml` из репозитория. Откройте файл в Safari: https://github.com/Dochsul/-/blob/claude/code-setup-plugin-c368la/deploy/cloud-init.yaml (нажмите Raw, скопируйте). Вместо строки `REPLACE_WITH_YOUR_PUBLIC_KEY` вставьте тот же публичный ключ (A6).
3. Нажмите **Create & Buy** — это покупка. Сделайте только после ⏸.
4. Скопируйте IP-адрес сервера в менеджер паролей.

**C3. DNS (домен).** 📱 В панели регистратора домена (или в DNS Tilda, если там) добавьте запись **A**: имя `api`, значение — IP сервера. Проверка через пару минут: в Safari откройте `https://api.<ваш-домен>` (сначала будет ошибка сертификата до запуска; это нормально).

**C4. Первый вход.** 📱 Приложение SSH: подключитесь как пользователь `deploy` к IP сервера (ключ из A6). Первые минуты cloud-init ставит Docker: дождитесь `cloud-init status --wait`.

**C5. Настройка одной командой.** 📱 На сервере:
```
cd /opt/aina && bash deploy/setup-server.sh
```
Скрипт спросит 11 вещей: домен API, адрес сайта Tilda, почту владельца, данные SMTP Brevo, ключ Revolut (можно пропустить), пароль копий (два раза), Backblaze (можно пропустить), пароль админ-панели (два раза), страницы после оплаты и отмены. Секреты вводятся скрыто. Скрипт сам:
- создаёт соль и хеш пароля админ-панели (пароль в открытом виде не сохраняется);
- пишет `.env` с правами 600;
- проверяет конфигурацию (`scripts/check-env.mjs`);
- запускает `deploy/deploy.sh` (при ошибке откатывается);
- проверяет `https://api.<домен>/api/health`.

Платежи при установке **выключены** (`PAYMENTS_ENABLED=false`).

**C6. Проверка.** 📱 Safari: `https://api.<ваш-домен>/api/health` → `"ok": true`. Затем `https://api.<ваш-домен>/admin` → вход паролем из C5.

**C7. Оригиналы PDF.** 💻 Скопируйте три PDF из библиотеки ChatGPT на сервер: `scp файл.pdf deploy@<IP>:/opt/aina/private/products/` (или через приложение SFTP на iPhone, например Termius). На сервере:
```
cd /opt/aina && node scripts/verify-files.mjs
```
Ожидается: три файла, каждый PDF, контрольные суммы выведены.

## Фаза D. Проверки без денег (песочница)

**D1. Включить песочницу.** 📱 На сервере:
```
bash deploy/payments-switch.sh sandbox-on
```
Скрипт откажется, если ключи не заданы. Реальных денег не списывается.

**D2. Тестовый заказ.** 📱 Откройте Tilda-сайт (после вставки блока магазина ChatGPT Work) и оформите тестовый заказ в песочнице. Проверьте: пришло письмо, ссылка скачивает PDF, в админ-панели появился заказ «оплачен».

**D3. Копии.** На сервере:
```
cd /opt/aina && docker compose -f deploy/docker-compose.yml --env-file .env run --rm backup node scripts/backup.mjs
docker compose -f deploy/docker-compose.yml --env-file .env run --rm backup node scripts/restore.mjs s3-latest --verify-only
```
Ожидается: копия создана, проверка восстановления без записи в рабочую базу прошла.

**D4. Почта.** Тестовый заказ должен прийти на почту покупателя (проверьте «Спам»). Если письмо не дошло — Brevo: домен отправителя должен быть подтверждён (SPF и DKIM в DNS).

## Фаза E. Боевой режим (⏸ только письменное решение владельца)

Все условия должны быть выполнены:
1. Merchant-аккаунт Revolut одобрен (B3 и письмо подтверждения).
2. Сквозной тест D2–D4 пройден.
3. Юрист проверил документы (`docs/LEGAL_PLAN.md`), адрес и НДС подтверждены.
4. Регулируемые услуги (консультации, меню, сопровождение) **не включаются**, пока юрист не подтвердит право их оказывать. Продаются только гайды.
5. Вы написали ассистенту «да, боевой режим для гайдов».

Тогда на сервере:
```
bash deploy/payments-switch.sh production-on
```
Скрипт дважды спросит фразы: `merchant-approved` и `owner-approved`. Без точного совпадения ничего не меняется.

Отключить в любой момент: `bash deploy/payments-switch.sh off`.

## Фаза F. Ежедневная работа с iPhone

- Админ-панель: `https://api.<ваш-домен>/admin`. Добавьте на экран «Домой» (Safari → Поделиться → На экран «Домой»).
- Состояние платежей: `bash deploy/payments-switch.sh status`.
- Обновления кода: `bash deploy/deploy.sh` (откатывается при ошибке).
- Логи: `docker compose -f deploy/docker-compose.yml logs --tail=100 api`.

## Таблица настроек, которые вводит скрипт (для проверки)

| Настройка | Откуда | Значение по умолчанию |
|---|---|---|
| `API_DOMAIN`, `SITE_URL` | домен (A3) | `https://api.<домен>` |
| `ALLOWED_ORIGINS` | адрес сайта Tilda | `https://<сайт>` (только сайт) |
| `CHECKOUT_SUCCESS_URL`, `CHECKOUT_CANCEL_URL` | страницы Tilda (A7) | `…/{locale}/merci/`, `…/{locale}/shop/` — подтвердите, что такие страницы существуют |
| `OWNER_EMAIL`, `OWNER_CHANNEL`, `CLIENT_CHANNEL` | почта владельца, SMTP | `smtp` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` | Brevo (A4) | `smtp-relay.brevo.com`, `587`, `starttls` |
| `REVOLUT_ENV`, `REVOLUT_API_KEY`, `REVOLUT_WEBHOOK_SECRET` | Revolut (B1–B2) | `sandbox` |
| `PAYMENT_PROVIDER`, `ENABLED_CURRENCIES`, `PAYMENTS_ENABLED` | сценарий | `revolut`, `EUR`, `false` |
| `LIVE_PAYMENTS_APPROVED` | только фаза E | пусто |
| `BACKUP_PASSPHRASE`, `BACKUP_PING_URL` | копии (A5) | пароль (не короче 20 символов), пинг — по желанию |
| `S3_*` | Backblaze (A5) | пусто — внешняя копия отключена |
| `ADMIN_PASSWORD_HASH` | пароль админки (C5) | создаётся скриптом |
| `IP_SALT` | генерируется | создаётся скриптом |
| `TRUST_PROXY` | `deploy/docker-compose.yml` | `true` (вписывать не нужно) |

`REGISTRATION_FILE` на сервере **не нужна**: это переменная для тестов. Юридические сведения и так не попадают в API.
