# Платежи: варианты, санкции и порядок запуска

Статус: **платежи выключены**. Реальные деньги не принимаются, пока владелец явно не подтвердит запуск (см. раздел 5). Тарифы, комиссии и правила провайдеров меняются, поэтому цифры здесь не приводятся: сверяйте с актуальными страницами провайдеров.

## 1. Варианты для бизнеса во Франции

| **Stripe Checkout** | Карты, Apple Pay, Google Pay, SEPA Direct Debit (по доступности). Платёжная страница Stripe, сайт не касается карточных данных | Цифровые продукты, предоплата консультаций | Аккаунт бизнеса Stripe (регистрация, проверка личности и бизнеса), решение о налогах на стороне Stripe | Реализован: сессия Checkout, webhook с проверкой подписи. Выключен |

**Рекомендация для старта:** Stripe Checkout для карт и цифровых продуктов, SEPA-перевод для консультаций. PayPal и Revolut — по желанию владельца.

## 2. Налоги (вопросы к бухгалтеру, не решения кода)

- НДС на цифровые услуги для потребителей в ЕС зависит от страны потребителя и от пороговых сумм ЕС (режим OSS). Для клиентов вне ЕС правила другие.
- Статус владельца (micro-entrepreneur, франшиза по НДС и т.п.) влияет на то, как указываются цены и НДС. Это в анкете (`docs/ANKETA.md`, раздел A).
- Код сохраняет суммы и валюту каждого заказа, поэтому данные для налоговой отчётности есть, но **не заменяют** бухгалтерию.

## 3. Санкции и клиенты из России

Принципы, которые заложены в код и которые нельзя ослаблять:

1. **Нет обхода.** Не используются чужие платёжные аккаунты, посредники, карты третьих лиц, смена страны или способа оплаты, чтобы обойти ограничения.
2. **Двойная проверка страны.** В Stripe Checkout страна берётся из адреса клиента. Если она в списке `business.blockedCountries`, webhook переводит заказ в статус `review_sanctions`: файлы не выдаются, владелец получает уведомление.
3. **Список стран не определён юридически.** Значения `RU` и `BY` — это заглушка. Список и правила для физических лиц из России определяет юрист по актуальным санкциям ЕС и Франции. Учитывается и политика Stripe (провайдер сам может не обслуживать такие страны).
4. **Консервативный режим по умолчанию:** пока юрист не дал заключение, рекомендуется полностью не принимать заказы из стран с санкциями.

Вопросы для юриста: применимы ли ограничения к продаже консультаций и цифровых гайдов; нужна ли проверка по спискам лиц; что делать с уже полученным платежом (возврат).

## 4. Безопасность платёжного потока

- Цены считаются на сервере по `src/config/catalog.mjs` (`server/validate.mjs`). Клиентская цена не принимается.
- Заказ переходит в «оплачен» только по подписанному webhook (`Stripe-Signature`, HMAC-SHA256, допуск 5 минут, повторы игнорируются по ID события).
- Сумма оплаты сверяется с суммой заказа. При расхождении файлы не выдаются.
- Idempotency-Key на создание сессии: повторный клик не создаёт второй заказ у провайдера.
- Секретный ключ и webhook-секрет только в переменных окружения, не в репозитории.
- Сайт не хранит номера карт и не получает их.

## 5. Чеклист запуска платежей (только после подтверждения владельца)

1. Владелец подтвердил: способы оплаты, цены, юридические документы (проверены юристом), налоговый режим.
2. Создан аккаунт Stripe и пройдена проверка. **Разрешение владельца на регистрацию обязательно.**
3. Тестовый режим Stripe: ключи `sk_test_…` и `whsec_…` в окружении сервера. Прогнать покупку тестовой картой (`4242 4242 4242 4242`), проверить выдачу файла, повтор ссылки, лимит скачиваний, истечение срока, страну из списка ограничений.
4. В Stripe Dashboard зарегистрировать endpoint `https://<домен>/api/webhooks/stripe` с событиями `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`.
5. Только после этого: `PAYMENTS_ENABLED=true` и ключи `sk_live_…` в продакшен-окружении. Перед этим — `npm run build:prod` без ошибок.
6. Проверить первый реальный заказ на небольшую сумму и возврат.
