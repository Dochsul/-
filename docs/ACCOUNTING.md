# Учёт заказов, платежей, комиссий и возвратов

Источник данных — база API (`data/app.db`, SQLite). Суммы хранятся в минимальных единицах (центы, копейки).

## Таблицы

| Таблица | Что хранит | Ключ от дублей |
|---|---|---|
| `orders` | Заказ: email, позиции, сумма и валюта с сервера, согласия (время), страна, статус | `id`, `provider_session_id` UNIQUE |
| `payments` | Подтверждённый платёж: брутто, комиссия, нетто, валюта расчёта комиссии | `provider_payment_id` UNIQUE |
| `refunds` | Возврат: сумма, причина | `provider_refund_id` UNIQUE |
| `downloads` | Персональные ссылки на PDF: хеш токена, срок, счётчик, отзыв | `token_hash` |
| `processed_events` | Обработанные события Stripe | `event_id` |

## Статусы заказа

| Статус | Значение | Файлы выданы |
|---|---|---|
| `pending_payment` | Создан, ждёт оплаты | нет |
| `paid` | Оплата подтверждена подписанным событием Stripe | да |
| `failed` / `expired` | Оплата не прошла / сессия истекла | нет |
| `review_amount` | Сумма оплаты не совпала с заказом — разобрать вручную | нет |
| `review_sanctions` | Страна из списка ограничений — разобрать с юристом, вернуть деньги | нет |
| `partially_refunded` | Частичный возврат | да (доступ сохраняется) |
| `refunded` | Полный возврат | ссылки отозваны |

## Комиссии

После оплаты сервер запрашивает у Stripe `balance_transaction` и записывает `fee` и `net` в валюте расчёта (`fee_currency`). Валюта расчёта может отличаться от валюты заказа. Если запрос не удался, комиссия остаётся пустой, а в экспорте стоит `fee_status = TO_RECONCILE`. Такие строки сверяются по отчёту Stripe (Balance → Reports) до закрытия периода.

## Возвраты

1. Возврат делается в Stripe Dashboard (полный или частичный).
2. Stripe присылает `charge.refunded`. Сервер записывает разницу к уже учтённым возвратам. Повтор события ничего не дублирует.
3. При полном возврате ссылки на файлы отзываются, владелец получает уведомление.
4. Возврат по банковскому переводу или вне Stripe этим механизмом не учитывается: его нужно внести вручную (не автоматизировано).

## Экспорт для бухгалтера

```bash
node scripts/export-accounting.mjs --from 2026-01-01 --to 2026-03-31            # без email
node scripts/export-accounting.mjs --from 2026-01-01 --to 2026-03-31 --with-email
```

Колонки: `type` (payment/refund), `date`, `order_id`, `provider`, `provider_id`, `currency`, `gross`, `fee`, `fee_currency`, `net`, `fee_status`, `country`, `items`, `order_status`, `reason` (+ `email`). Возвраты — отрицательная сумма. В консоль выводятся итоги по каждой валюте и число комиссий к сверке.

Файлы экспорта содержат персональные и финансовые данные: папка `exports/` исключена из git. Хранить по правилам бухгалтерии, передавать бухгалтеру защищённым способом.

## Что не автоматизировано

- Выставление счетов (factures) — правила зависят от статуса бизнеса и НДС. Вопрос к бухгалтеру (анкета A5).
- Учёт заказов, оплаченных вне Stripe (перевод, Revolut, PayPal).
- Учёт заявок из нативной формы Tilda (они в CRM Tilda).
