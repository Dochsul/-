# Запуск AINA Évidence: пошаговая инструкция для владельца

Эта инструкция написана без технических знаний. Каждый шаг помечен:

- **👤 Вы** — нужны ваши личные действия: регистрация, документы, карта, подтверждение расходов, пароли.
- **🤖 Ассистент** — то, что делает Claude в репозитории.
- **⏸ Стоп** — дальше нельзя идти без вашего решения.

Ничего не покупается и не включается, пока вы не скажете «да» на конкретный шаг.

## 0. Главные правила безопасности

1. **Пароли и ключи — только в менеджере паролей** (например, iCloud Keychain, Bitwarden, 1Password). Не отправляйте их в чат, письма и GitHub. Ассистент никогда их не попросит.
2. **Регистрационные данные (SIREN и т. д.) не публикуются.** Репозиторий на GitHub публичный. Ваши данные хранятся в файле `private/registration.json` **на вашем компьютере** и в зашифрованной копии (раздел 2).
3. **Регистрация micro-entreprise не даёт права на регулируемую деятельность.** По нашему пониманию, во Франции титул «diététicien(ne)» охраняется законом; точный объём и последствия для вас подтвердит юрист. Регистрация «libérale non réglementée» не означает, что вы можете оказывать такие услуги под этим титулом. Страницы консультаций и квалификация остаются черновиками, пока юрист или профессиональная организация не подтвердят это в письменном виде (шаг 9.2).
4. **Реальные платежи выключены** и включаются только в конце, после всех проверок и вашего письменного решения (раздел 9).

## 2. Регистрационные данные: безопасное хранение

Цель: данные не потеряются, если облачная рабочая среда ассистента будет переустановлена, и не попадут на GitHub.

**Что нужно сделать (на вашем компьютере):**

1. Скачайте или откройте из репозитория `docs/registration.template.json` (шаблон без значений).
2. Создайте папку `private` в папке проекта на вашем компьютере (если её нет) и скопируйте туда шаблон под именем `registration.json`.
3. Заполните поля из ваших документов: название, форма, SIREN, RCS/RM (или «non applicable», если не применимо — уточните у бухгалтера), адрес, директор публикации. **Если не уверены — оставьте `null`.** Ничего не угадывайте.
4. **Зашифруйте копию** (пароль выбираете вы, не короче 20 символов, сохраните его в менеджере паролей):
   ```bash
   read -rs PASS && printf '%s' "$PASS" | node scripts/registration-seal.mjs seal; unset PASS
   ```
   Появится файл `private/registration.json.enc`. Его можно хранить в облаке (Google Drive, iCloud), а пароль — в менеджере паролей. Без пароля файл не открыть.
5. Проверьте, что `git status` **не показывает** папку `private/`. Она закрыта `.gitignore`. Если что-то из неё видно — остановитесь и сообщите ассистенту.
6. Восстановить можно на любом компьютере:
   ```bash
   read -rs PASS && printf '%s' "$PASS" | node scripts/registration-seal.mjs open; unset PASS
   ```

👤 **Вы:** заполнить данные, выбрать пароль, хранить `.enc` и пароль в двух разных местах.
🤖 **Ассистент:** не публикует значения и не трогает `private/`.

## 5. Сервер Hetzner (API для оплаты и выдачи PDF)

Ссылка: https://www.hetzner.com/cloud, консоль https://console.hetzner.cloud

1. 👤 **Регистрация.** Email, пароль, телефон, подтверждение личности (Hetzner может попросить документ). Выберите страну, укажите реквизиты.
2. 👤 **Способ оплаты** — банковская карта или SEPA (по инструкции консоли). Это ваш платёж, ассистент его не видит.
3. 👤 **Создание сервера** в консоли (New project → Add server):
   - Location: Falkenstein, Nuremberg или Helsinki (ЕС).
   - Image: **Ubuntu 24.04**.
   - Type: **самый маленький общий сервер (Shared vCPU) не меньше 2 vCPU и 2–4 ГБ RAM**. Сейчас в линейке CX22 или CX23 — выберите актуальный в консоли. Цену смотрите в консоли.
   - Networking: включите публичный IPv4 (нужен, чтобы домен указал на сервер). Проверьте, что сумма в калькуляторе совпадает с вашим ожиданием.
   - SSH key: 👤 создайте ключ на своём компьютере (`ssh-keygen -t ed25519`) и вставьте **публичную** часть (файл `.pub`). Приватную часть не передавайте никому.
   - Cloud config (user data): 🤖 ассистент подготовит значения из `deploy/cloud-init.yaml`; вы заменяете строку `REPLACE_WITH_YOUR_PUBLIC_KEY` на свой публичный ключ.
4. 🤖 После запуска сервера ассистент покажет шаги `deploy/deploy.sh` (Docker, брандмауэр 22/80/443, автообновления безопасности).
5. 👤 **Доступ:** в консоли Hetzner скопируйте IP-адрес сервера. Остальные команды выполняются по SSH; при затруднении позовите технического специалиста на час (разовая помощь, оплата по договорённости).

⏸ **Стоп 2:** сервер создаётся только после вашего «да» на раздел 4.

1. 👤 Выберите регистратора домена и купите домен (или поддомен у существующего домена).

## 7. Почта покупателям: Brevo

Ссылка: https://www.brevo.com (бесплатная регистрация). SMTP-настройки: в аккаунте откройте **Settings → SMTP & API** (путь может немного отличаться, ищите слово SMTP).

1. 👤 Зарегистрируйтесь на Brevo по почте, которую вы используете для бизнеса (globalainanutrition@gmail.com — по вашему выбору, см. анкету).
2. 👤 Подтвердите почту и телефон. Brevo может одобрить отправку не сразу — это нормально.
3. 👤 **Добавьте домен отправителя** (раздел Senders & IP → Domains): вставьте записи SPF и DKIM в DNS (раздел 6). Без этого письма попадут в спам.
4. 👤 **Создайте SMTP-ключ** (SMTP & API → Generate a new SMTP key). Скопируйте ключ в менеджер паролей. **Логин** SMTP показан на той же странице.
5. 🤖 В `.env` на сервере ассистент (или вы по инструкции) укажет:
   - `SMTP_HOST` — адрес сервера SMTP из страницы Brevo (сверьте; обычно `smtp-relay.brevo.com`)
   - `SMTP_PORT` — 587
   - `SMTP_SECURE` — `starttls`
   - `SMTP_USER` — логин из Brevo
   - `SMTP_PASS` — SMTP-ключ (👤 вы вносите сами в файл `.env` на сервере, не в чат)
   - `MAIL_FROM` — адрес отправителя на вашем домене
   - `MAIL_FROM_NAME` — `AINA Évidence`
   - `OWNER_CHANNEL=smtp`, `CLIENT_CHANNEL=smtp`
6. Лимит бесплатного тарифа — 300 писем в день. Для запуска достаточно. При превышении Brevo предложит платный тариф (решение за вами).

⏸ **Стоп 3:** подключать Brevo к боевой системе можно только когда домен подтверждён.

## 8. Копии базы: Backblaze B2

Ссылка: https://www.backblaze.com/cloud-storage, консоль https://secure.backblaze.com

1. 👤 Зарегистрируйтесь и подтвердите почту и способ оплаты (бесплатный лимит — 10 ГБ; карта нужна для аккаунта).
2. 👤 **Создайте бакет** (B2 Cloud Storage → Buckets → Create a Bucket):
   - имя, например `aina-evidence-backups` (уникальное, как предложит консоль);
   - тип: **Private** (закрытый);
   - регион: EU (например, eu-central-003) — проверьте точное название региона в карточке бакета.
3. 👤 **Создайте ключ приложения, ограниченный этим бакетом** (App Keys → Add a New Application Key). Скопируйте `keyID` и `applicationKey` в менеджер паролей сразу: второй раз он не показывается.
4. 🤖 В `.env` на сервере:
   - `S3_ENDPOINT` — адрес вида `https://s3.<регион>.backblazeb2.com` (сверьте в консоли бакета)
   - `S3_REGION` — регион, например `eu-central-003`
   - `S3_BUCKET` — имя бакета
   - `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` — ключ из шага 3 (👤 вносите сами)
5. 👤 **Пароль шифрования копий** `BACKUP_PASSPHRASE` — не короче 20 символов, в менеджере паролей. **Если он потерян, копии нельзя прочитать.** Это важнее всего остального в этом разделе.
6. Необязательно: `BACKUP_PING_URL` из healthchecks.io — пришлёт вам письмо, если копирование остановилось. Это сторонний сервис, решение за вами.

**Что копируется:** база (заказы, платежи, заявки). **PDF не копируются** (их оригиналы лежат у вас в библиотеке ChatGPT и на сервере, см. раздел 10).

## 9. Revolut Business и Merchant API

Официальная документация: https://developer.revolut.com/docs/merchant/merchant-api. Подробная пошаговая инструкция проекта: `docs/REVOLUT.md`.

1. 👤 **Откройте аккаунт Revolut Business** (https://www.revolut.com/business, через приложение или сайт). Пройдите проверку бизнеса (документы, в том числе выписка SIRENE/INSEE). Тариф подбирайте по официальной странице тарифов: источники, которые я проверял, расходятся по ценам, поэтому сверьте сами.
2. 👤 **Заявка на приём оплат (Merchant).** Спросите в поддержке Revolut письменно: **разрешены ли продажи цифровых товаров (PDF) через Merchant API для вашего типа бизнеса.** По найденным материалам, цифровые товары относятся к ограниченным категориям. Ответа на этот вопрос в открытых источниках я не нашёл. Ответ сохраните в почте.
3. 👤 **Песочница (Sandbox).** Создайте ключ песочницы в Revolut Business (раздел API / Merchant). Ключ **не присылайте в чат**; вносите в `.env` на сервере.
4. 👤 **Webhook.** Создайте webhook на адрес `https://api.<ваш-домен>/api/webhooks/revolut` с четырьмя событиями: `ORDER_COMPLETED`, `ORDER_CANCELLED`, `ORDER_PAYMENT_DECLINED`, `ORDER_PAYMENT_FAILED`. Revolut покажет секрет `wsk_…` — сохраните его в менеджере паролей и передайте ассистенту **только через** `.env` (👤 вы).
5. 🤖 **Проверка песочницы** на сервере: `node scripts/revolut-test.mjs check` (один заказ, без денег). Результат сверяется с таблицей в `docs/REVOLUT.md`.
6. 👤 **Сквозной тест в песочнице** с сайта Tilda: один заказ, проверка письма и выдачи PDF.
7. ⏸ **Стоп 4 — боевой режим** (`REVOLUT_ENV=production`) только после: письменного подтверждения Revolut по цифровым товарам, одобрения Merchant-аккаунта, успешного сквозного теста в песочнице и вашего письменного решения.
8. 👤 Способы оплаты (карты, Apple Pay, Google Pay) включаются в настройках Merchant. Укажите их в анкете (`business.paymentMethods`).
9. 👤 Юрлицо Revolut, с которым вы заключаете договор, указывается в юридических текстах (`business.paymentProviderEntity`). Возьмите его из договора.
10. Комиссии: 👤 выгрузите выписку Revolut (CSV), ассистент покажет, как импортировать комиссии (`npm run fees:import`, сначала сухой прогон). Выписку **без реквизитов карт** пришлите ассистенту для проверки формата.

## 11. Сервер: запуск

1. 🤖 Ассистент проводит по `deploy/deploy.sh`: клонирование репозитория в `/opt/aina`, заполнение `.env` (права `600`), проверка конфигурации `scripts/check-env.mjs`, запуск контейнеров (API, Caddy с HTTPS, копии).
2. 👤 Вы вносите значения секретов в `.env` сами: `REVOLUT_API_KEY`, `REVOLUT_WEBHOOK_SECRET`, `SMTP_PASS`, `BACKUP_PASSPHRASE`, `S3_*`, `ADMIN_PASSWORD_HASH`, `IP_SALT`.
   Значения `TRUST_PROXY=true` (задаёт `deploy/docker-compose.yml`), `SITE_URL` и `API_DOMAIN` (ассистент пропишет по вашему домену) вам вписывать не нужно.

4. Админ-панель: `https://api.<ваш-домен>/admin` (инструкция `docs/ADMIN.md`). Откройте на iPhone.
5. **Пока платежи выключены:** `PAYMENTS_ENABLED` не задаётся (или `false`). `LIVE_PAYMENTS_APPROVED` остаётся пустым.

## 13. Юридические документы

1. 🤖 Тексты построены по шаблонам из `src/legal/` и подставляют данные из личного файла. Без вашего файла вместо значений стоят заглушки.
2. 👤 **Не публикуйте** страницы «Mentions légales», «CGV», «Confidentialité», «Remboursement», «Produits numériques» до проверки юристом.
3. 👤 Пункты, которые нужно решить до публикации (анкета, раздел L и K):
   - адрес регистрации;
   - режим НДС (освобождение или нет);
   - хостинг сайта (название и адрес поставщика);
   - медиатор потребителей (обязателен во Франции, ищите через официальный список);
   - сроки хранения данных, сроки возврата и отмены, применимое право и суд;
   - список стран покупателей (решение юриста);
   - юрлицо Revolut и способы оплаты.
4. 👤 **Юрист:** найдите юриста по французскому праву потребления и персональных данных. Оплата его услуг — ваше решение. Ассистент не может заменить проверку юристом.
