## 2. Ваша существующая платёжная ссылка

`https://checkout.revolut.com/pay/29470c83-404b-4a43-aba7-8926bcfb7032` — это ссылка «Pay by link», созданная в интерфейсе Revolut Business.

- Сумма в такой ссылке задаётся при её создании, а не при каждом заказе. Как правило, одна ссылка даёт одну и ту же сумму всем покупателям, поэтому «точная сумма для каждого заказа» через неё не получается (проверено по описанию, без открытия ссылки).
- Из неё не видно, какой заказ оплачен. Чтобы выдать PDF, нужна связь «оплата → наш заказ». Через API она есть (`merchant_order_data.reference`), через ссылку — не подтверждена.
- Поэтому **автоматическую выдачу через эту ссылку не строим**. Ссылку можно оставить для ручных разовых продаж, но тогда файл вы высылаете вручную после проверки оплаты.
- Я не открывал ссылку и ничего не оплачивал.

**Решение:** продажи идут через Merchant API (заказ создаётся на сервере с точной суммой). Ссылка остаётся запасным ручным вариантом.

## 3. Что уже реализовано в коде

- Создание заказа на сумму, посчитанную сервером (`server/revolut.mjs`). Клиентская сумма не принимается.
- Webhook `/api/webhooks/revolut`: подпись, допуск времени 5 минут, защита от повторов, атомарный захват заказа (две одновременные доставки не выдают файлы дважды).
- Перед выдачей PDF сервер **сам запрашивает заказ у Revolut** и сверяет состояние, сумму, валюту и номер заказа. Тело webhook не считается доказательством оплаты.
- Санкции: страна покупателя проверяется до создания заказа и повторно по стране, которую сообщает Revolut.
- Учёт: платёж, комиссия (пока не сверена), возвраты, экспорт CSV (`docs/ACCOUNTING.md`).
- Stripe сохранён как отключённый запасной модуль: включается только при `PAYMENT_PROVIDER=stripe`. Регистрация в Stripe не нужна.

## 4. Пошаговая инструкция для вашего аккаунта Revolut

Выполняйте по порядку. Пункты с **⚠** требуют вашего решения или оплаты.

**Шаг 1. Тип аккаунта.** Войдите в Revolut Business (бизнес-аккаунт). Проверьте, что бизнес верифицирован. Без этого мерчант-аккаунт не подать.
- Тариф Revolut Business может стоить денег. **⚠ Не переходите на платный тариф без вашего решения.**

**Шаг 2. Проверка категории.** Откройте [страницу рестриктивных категорий](https://help.revolut.com/business/help/merchant-accounts/setting-up-a-merchant-account/prohibited-and-restricted-industries-business-models-for-a-merchant-account/). Цифровые товары там помечены как рестриктивные. Напишите в поддержку Revolut (раздел «Помощь» в приложении) и попросите подтвердить, что продажа PDF-гайдов из Франции возможна, на каких условиях и какой резерв. Ответ сохраните. **Без этого подтверждения запускать продажи не стоит.**

**Шаг 3. Заявка на мерчант-аккаунт.** В Revolut Business: раздел мерчант-аккаунтов (Merchant) → подать заявку. Укажите категорию «онлайн-консультации и цифровые образовательные материалы». Заявку подаёт владелец бизнеса, все проверки проходит он.
- **⚠ Условия комиссий** придут в договоре. Сравните их до подписания.

**Шаг 4. Песочница.** Откройте [API Console](https://developer.revolut.com/docs/api/merchant) и переключитесь на **Sandbox**. Создайте ключ Merchant API для песочницы. Ключ — секрет. Не отправляйте его в чат и не вставляйте в код. Он вносится **только** в GitHub-секрет `REVOLUT_SANDBOX_API_KEY` (для ручной проверки) или в `.env` на сервере.

**Шаг 5. Webhook.** Создайте webhook на адрес `https://<ваш-api-домен>/api/webhooks/revolut` (создание через Merchant API: [create webhook](https://developer.revolut.com/docs/merchant/set-webhook); точное место в интерфейсе уточните в Console). Подпишите события:
- `ORDER_COMPLETED`
- `ORDER_PAYMENT_DECLINED`
- `ORDER_PAYMENT_FAILED`
- `ORDER_CANCELLED`

После создания Revolut покажет **signing secret**, начинается с `wsk_`. Скопируйте его в `.env` как `REVOLUT_WEBHOOK_SECRET`. Секрет в чат не присылайте.

**Шаг 6. Настройки сервера (.env, права 600):**
```
PAYMENT_PROVIDER=revolut
REVOLUT_ENV=sandbox
REVOLUT_API_KEY=<ключ песочницы>
REVOLUT_WEBHOOK_SECRET=wsk_<из шага 5>
REVOLUT_API_VERSION=2024-05-01
PAYMENTS_ENABLED=true          # только в песочнице, пока не одобрено владельцем
ENABLED_CURRENCIES=EUR
```

**Шаг 7. Проверка в песочнице (без денег).**
- Ручная проверка ключа: GitHub → Actions → «Revolut sandbox check» → Run workflow (нужен секрет `REVOLUT_SANDBOX_API_KEY`).
- Сквозной тест с Tilda-блоком в вашем окружении: купите гайд в песочнице тестовой картой Revolut Sandbox (реквизиты тестовых карт — в документации песочницы Revolut). Ожидаемо:

| Сценарий | Ожидаемый результат |
|---|---|
| Оплата комплекта 19,90 € | Заказ `paid`, 3 ссылки в письме, 3 PDF скачиваются |
| Повтор webhook | Новых ссылок нет |
| Отказ карты | Заказ остаётся открытым, повторная оплата доставляется |
| Неверная подпись webhook | Ответ 400, заказ не меняется |
| Страна из списка ограничений | Заказ `review_sanctions`, файлы не выдаются |
| Возврат | Учитывается командой `npm run refund:record`, полный возврат отзывает ссылки |

**Шаг 8. Боевой режим — только с вашим явным разрешением.** Когда мерчант-аккаунт одобрен и вы решили запускать:
1. Создайте боевой ключ и боевой webhook (шаги 4–5 в боевом режиме).
2. В `.env`: `REVOLUT_ENV=production`, `LIVE_PAYMENTS_APPROVED=owner-approved`.
3. Сервер без `LIVE_PAYMENTS_APPROVED` с боевым режимом **не запустится**. Это защита от случайного включения.

**Шаг 9. Способы оплаты.** Включите в мерчант-настройках нужные способы (карты, Apple Pay, Google Pay — что доступно вашему аккаунту). Перечислите их в `src/config/business.mjs` в поле `paymentMethods`. До этого юридические тексты покажут подсветку.

**Шаг 10. Юрлицо Revolut.** В договоре с Revolut указано, какое юрлицо Revolut контрагент (зависит от страны бизнеса). Внесите его в `business.paymentProviderEntity`. Сейчас это поле пустое, юридические тексты его подсвечивают.

**Шаг 11. Комиссии и сверка.** Раз в месяц скачайте выписку (CSV) из Revolut Business. Файл должен содержать колонки `reference` (номер заказа, см. ниже), `fee` и `currency`. Точный формат выписки я **не проверил**: откройте свою выписку и сверьте. Затем:
```
npm run fees:import -- выписка.csv            # сухой прогон, ничего не пишет
DB_FILE=data/app.db npm run fees:import -- выписка.csv --apply
```
Проверьте, попадает ли наш номер заказа (передаётся как `merchant_order_data.reference`) в выписку. Это проверяется в песочнице на шаге 7. Если номера в выписке нет, комиссии остаются «к сверке»: это честная отметка, а не ошибка. Сверку тогда делают по сумме и дате вручную.

**Шаг 12. Возвраты.** Возврат делаете в Revolut Business. Затем зафиксируйте его в учёте:
```
DB_FILE=data/app.db npm run refund:record -- --order <номер заказа> --amount 9.90 --ref <номер возврата Revolut>
```
Повторный запуск с тем же `--ref` ничего не меняет. Сумма не может превысить оплаченную.

## 5. Законность платежей из разных стран

- **Продавец:** бизнес из Франции. Мерчант-аккаунт Revolut доступен бизнесу с верификацией; список стран на справке различается по регионам. Проверьте, что Франция в вашем списке, и что категория цифровых товаров допустима (шаг 2).
- **Покупатели:** магазин предлагает ограниченный список стран (`src/config/countries.mjs`). Список нужно подтвердить с юристом и с Revolut.
- **Санкции:** Россия и Беларусь исключены сервером (`config.blockedCountries`) и не предлагаются в форме. Это заглушка до решения юриста. **Не обходить:** чужие аккаунты, посредники, смена страны в форме — не поддерживаются и не будут внедряться.
- **Что не найдено:** официальные санкционные правила Revolut для клиентов из других стран в доступных источниках не найдены. **Проверьте** на странице Revolut по ограничениям или у поддержки и сохраните ответ.
- **НДС:** для клиентов в ЕС цифровые услуги облагаются НДС страны покупателя при превышении порогов ЕС (режим OSS). Это вопрос к бухгалтеру; код хранит валюту и сумму, но не считает налоги.
